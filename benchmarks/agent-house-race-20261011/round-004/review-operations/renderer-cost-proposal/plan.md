# Read-only post-R004 shader candidate

No renderer defect or cause of the R004 engine gap is established here. R004 A authors one directional sun plus ambient, default environment, MSAA4 and 8-sample SSAO; stucco/stone/asphalt use real normal textures with authored tangents, and blue materials use clearcoat0.55. Its very different baked/unindexed geometry remains a major confound. These are source facts, not timing attribution.

**First future candidate: B1, skip an unused directional shadow sample using the actual direct-light zero predicate.** `standard-shader-source.ts:180` returns exact +zero when `max(dot(normal,lightDir),0)<=0`, before half-vector/BRDF/lobe work. Current `standard-shader-shadow-sampling.ts:604` samples the shadow first. Clearcoat/sheen/iridescence source rewrites occur after that return. Sampling normal maps/material textures and IBL stays outside the new guard; ambient, area, transmission/volume, emission and global receiver factors remain intact.

The sketch is a proposal, not a validated patch. Use the final composed shader and its actual authoritative normal/light arguments. Initially enable only ordinary nonclustered, noncascaded single-2D directional receiver configurations; exclude spot, point/multi, arrays, marker and clustered routes. This avoids breaking later literal clustered-loop replacement. All excluded generated WGSL must remain byte-identical.

Correctness obligation: old returned direct zero times a finite nonnegative shadow factor equals new returned direct zero times1. The current helper returns1 for invalid projection/matrix bounds and sanitizes raw-visibility NaNs before mixing finite strength; engine packing maps nonfinite strength to1. The sketch additionally retains original sampling when the actual strength is NaN, preserving exported raw-buffer 0*NaN behavior; its negated <= predicate preserves NaN-NoL fallthrough. Native derivative/uniformity, exact final lobe guard placement and pixel equivalence remain unproved and must pass before adoption. No gains are imagined; the compiler may already remove this work.

**Separate lower-priority candidate:** replace only the existing marker/cluster directional `select(1,sampleShadow,ownerPredicate)` with an actual branch. WGSL select eagerly evaluates the discarded sample; old false branches already produce1. Do not add owner gating to ordinary single-map loops: those currently apply the shared map to every directional light. R004 has one sun and no marker route, so this is not its identified cost or an adoption case by itself.

**No-op-lobe/IBL proposals held:** absent features already omit code; BRDF/proof IBL are mutually exclusive. Roughness1 and metallic0 do not make specular IBL zero. Zero clearcoat/sheen/iridescence/transmission texture paths have derivative and IEEE 0*NaN/mix obligations; no safe broad removal was established. Any such ablation must be separate.

Future proof sequence under separate root approvals: (1) CPU-generate exact full current baseline/B1 WGSL, assert actual declaration/call arity plus the unchanged first zero-return and correct normal argument; retain every output and byte-identical excluded route. (2) One native parity invocation retaining the existing32 mixed-owner/default/clamp/filter/material/route cases plus16 facing probes (base/normal/clearcoat/combined by positive/zero/negative/mixed-NoL), 48pairs/96frames, RGBA16 raw byte equality and allfinite valid-engine channels; include untimed predicate/owner f32 oracle and raw-buffer NaN fallback diagnostics. (3) One paired timing invocation: common generic folded surfaces with sun+ambient+IBL+normal map, and an all-lit control with identical material/lighting; 16warmup per variant/workload then AB/BA/AB,32samples/block, total448frames. All compilation/upload/warmup/capture/hash outside native submit/completion fences. Keep queue30s, aggregate900s/verifier960s, zero retries and existing recording caps. Common all3 minimum improvements must exceed max(3%baseline minimum,0.25ms); all-lit control must not show a regression exceeding that same allowance. Report every median/range (including flat or slower medians) and no end-to-end/hardware/engine ranking. A second stress-only gain cannot justify adoption. All work uses runtime_pressure -> trusted loopback -> runVerifiedScene under an exclusive root window; no frozen scene/harness/rubric changes.
